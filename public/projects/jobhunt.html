jobhunt.coach

The job-search process that got me hired, turned into software.

live · invite-gated · multi-user · sole engineer · jobhunt.coach ↗

what it is

jobhunt.coach runs a job search end to end from a single chat-driven dashboard. It interviews you about your career the way an oral historian would, one question at a time, and builds a structured career narrative from your answers. Paste a job description and it analyzes your fit, then writes a tailored resume and cover letter, compiled from LaTeX to a real PDF. Before an interview, it produces per-interviewer prep: likely questions, answers in your own voice, grounded in your actual history.

It's the productized version of a methodology I first ran manually on my own job search — the same process that landed my current role.

how it works

  1. Oral history. Upload a resume and the assistant interviews you in chat, maintaining a live profile preview as you answer. The result is a career narrative in two forms: markdown for tailoring, structured JSON for LaTeX token substitution.
  2. Fit + tailored PDF. Paste a JD or a URL. The assistant runs an honest fit analysis (strengths, real gaps, disqualifiers), then generates a tailored LaTeX resume and cover letter compiled by Tectonic. If compilation fails, the model repairs the .tex from the compile log, up to four attempts.
  3. Interview prep. Per-interviewer dossiers with likely questions and answers in your voice, grounded in the profile rather than invented.

Turns are durable: a long agentic run survives a page reload, because the client polls a turn ID instead of holding a connection open. One turn can chain up to 20 tool actions, so a compound request like "find jobs, analyze the top three, draft resumes for the best two" completes without babysitting.

why it doesn't flatter you

One design rule serves the goal of actually getting hired: every model call runs under a methodology prompt that forbids invented facts and requires fit analyses to surface real gaps and disqualifiers, not just strengths. Resumes built on flattery fail in the first interview. An honest read of your fit means you spend effort on jobs you can win and walk in with answers that hold up.

under the hood

  • Backend: Python 3.13 + FastAPI as a pure JSON API; agentic loop with auto tool-choice, batched execution, observe, repeat.
  • LLM layer: provider-agnostic over raw httpx, no vendor SDKs — Anthropic, OpenAI, Cerebras, Gemini, OpenRouter and more behind one complete() interface.
  • Frontend: React SPA (TypeScript + Vite), a single chat shell with a results panel — built with heavy AI-coding-agent assistance, which felt like the appropriate way to build it.
  • Persistence: stdlib sqlite3, no ORM; database and generated PDFs live on a Fly.io volume.
  • Edge: Cloudflare Worker fronting the Fly.io app; invite-gated multi-user auth with CSRF protection; Sentry, e2e tests, ruff and mypy in CI.
  • Billing: Stripe subscriptions built with signed-webhook verification, currently shipped dark behind a rollout flag.
